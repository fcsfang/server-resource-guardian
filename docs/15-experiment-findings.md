# 实验关键结论汇总

更新时间：2026-09-19

> 用途：将 EXP-001 ~ EXP-006 的技术发现汇总为可执行的工程结论，供架构设计和汇报使用。每条结论标注来源实验和结论类型（观测/判断）。

## 1. 资源危机的失效机制

| 发现 | 结论类型 | 来源 | 工程意义 |
| --- | --- | --- | --- |
| 宿主机级内存耗尽导致系统崩溃（非 SSH 变慢） | 观测 | EXP-005 | 监控必须在内存到达临界前告警，而非等系统不响应 |
| sshd 被内核 OOM killer 保护（oom_score_adj=-1000） | 观测 | EXP-005 | OOM killer 不会杀 sshd；SSH 失效 = 整机崩溃 |
| Docker 容器内资源消耗被 cgroup 隔离 | 观测 | EXP-002/005 | 容器内的内存泄漏不会拖垮宿主机 |
| Docker 容器无限制时多容器竞争可达 94%+swap 85% | 观测 | EXP-005 | 多容器无限制竞争会逼近系统极限 |
| CPU 100% 时 SSH 仍可用（延迟 117-483ms） | 观测 | EXP-004 | CPU 竞争不是主要风险，**内存才是** |
| --pids-limit 有效防止容器内 fork bomb | 观测 | EXP-005 | PID 限制是有效的资源边界手段 |

## 2. 检测-定位-处置-恢复管道时效

| 阶段 | 耗时 | 来源 | 说明 |
| --- | --- | --- | --- |
| 泄漏开始 → 警告（70%） | 110s | EXP-006 | 可用预警窗口 |
| 警告 → 临界（85%） | 31s | EXP-006 | 危机升级窗口 |
| 定位肇事容器（docker stats） | **< 1s** | EXP-006 | 即时 |
| 处置：docker stop | **13s** | EXP-006 | 瓶颈（SIGTERM 等待） |
| 处置：docker kill（估算） | **~1s** | EXP-006 | 仅作为受控动作候选，未形成通用默认策略 |
| 恢复确认 | 2s | EXP-006 | — |
| **总响应时间** | **15s（可优化至 ~3s）** | EXP-006 | 远快于崩溃时间（>60s） |

## 3. 架构决策

| 结论 | 对架构的影响 | 来源 |
| --- | --- | --- |
| Guardian 必须自己做实时检测（~1s），不能依赖 Beszel | Beszel 采样周期 60s，从 70% 到 85% 只需 31s，等 Beszel 发现时可能已崩溃 | EXP-006 |
| Beszel 保留为历史数据看板和告警通知 | Beszel 的长处是存储、可视化和历史告警，不适合实时检测 | EXP-006 |
| docker stats 是定位肇事容器的最快方式 | < 1s 返回，比查 Beszel API 或 cgroup 文件更快 | EXP-006 |
| docker kill 比 docker stop 更快 | 13s → ~1s，但只能作为明确授权、明确保护名单下的最后手段 | EXP-006 |
| Docker 资源限制（--memory/--cpus/--pids-limit）是可选的预防手段 | 只有业务确认兼容时才配置，不是项目统一目标，也不是 Guardian 的默认动作 | EXP-002/005 |
| Guardian 的最小功能 = 实时风险检测 + 对象定位 + 保护判断 + 分级处置 + 恢复验证 | 不需要重写 Beszel 或内核 OOM 逻辑 | EXP-003/006 |
| 无 Guardian 时的 global OOM 与 Guardian 止损已形成同条件本地对照 | Guardian 的核心价值是资源危机升级前自动止损，而不是统一给容器加资源上限 | EXP-021 |

## 4. Guardian 最小功能清单

基于 EXP-003 缺口分析和 EXP-006 管道验证，Guardian 的主线是“发现宕机风险并自动处理”，不是给所有容器统一加内存限制：

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 实时风险信号采集 | P0 | 轮询 `/proc/meminfo`、PSI、cgroup、Docker stats/events 等，识别趋势和临界风险 |
| 风险判定 | P0 | 组合利用绝对阈值、增长速率、持续时间、压力和业务影响，避免单点瞬时阈值误触发 |
| 对象定位 | P0 | 确定风险容器、进程或服务，并记录对象身份，避免 PID/容器重用误处理 |
| 保护名单与策略校验 | P0 | 配置不可处理对象、可处理对象、允许动作、冷却和熔断规则 |
| 分级处置 | P0 | 支持 `observe`、`simulate`、通知、优雅停止/重启和受控终止；默认不执行破坏性动作 |
| 恢复验证 | P0 | 检查资源是否回落、服务是否健康、动作是否达到预期；失败时升级而不是静默结束 |
| 动作前快照与审计 | P1 | 保存 `docker inspect`、进程信息、指标、决策原因和动作结果 |
| 通知与升级 | P1 | 写入审计日志并按策略调用 webhook 或其他值班通道 |
| 业务级资源限制适配 | P2 | 仅为明确允许的业务提供配置入口，不作为通用自动动作 |
