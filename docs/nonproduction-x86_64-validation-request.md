# x86_64 非生产验证申请包

状态：待负责人审批。本文只用于申请和准备，不表示已经连接或验证任何非生产/生产服务器。

## 一、申请目的

申请在一台获批的 x86_64 非生产服务器上，先以只观察模式验证 Guardian 的安装、开机运行、资源监控、维护入口和告警送达。

本申请不申请：

- 生产服务器连接、安装或读取生产凭据；
- 自动停止容器、自动重启服务或自动删除文件；
- 生产自动模式；
- 未经批准的压力测试或业务影响测试。

本地已经证明的内容只代表本地 ARM64 disposable 虚拟机，不能直接代表 x86_64 非生产或生产环境。当前 Beszel 证据只有本地页面和告警历史，真实管理员通知送达还没有完成，因此通知渠道和收件人授权是本申请的前置项。

## 四、执行边界和步骤

### 1. 开始前检查

- 负责人确认服务器确实是非生产，业务负责人确认可以进入维护窗口。
- 在目标机运行 `python3 scripts/guardian-x86-preflight.py --output /tmp/guardian-x86-preflight.json`；结果必须为 `ready_for_observe_install: true`。该命令只读，不代表获得安装或自动动作授权。
- 记录 Guardian、Beszel、Docker、SSH、磁盘和服务的初始状态；不读取环境变量、Token、密码、密钥、业务数据或容器卷内容。
- 确认 SSH、带外或现场恢复方式在测试前可用。
- 确认真实告警渠道、授权收件人和送达测试目标已经填写并获批。
- 确认回滚文件保存位置和回滚负责人在线。

### 2. 只观察安装

- 使用经过审核的部署包，在负责人确认的非生产维护窗口执行安装。
- 安装后必须保持 `observe` 模式、自动动作关闭、允许处理名单为空、Docker Broker 关闭、预留恢复边界关闭。
- Guardian Runtime 不能加入 Docker 管理组，不能以 root 运行；容器数据只能通过只读采集入口获取。
- 安装过程不停止容器、不重启服务器、不删除业务文件、日志、镜像或容器数据。
- 当前本地安装脚本明确限制在 `local-disposable` 环境；非生产执行前必须由负责人批准对应的非生产部署入口，不能直接绕过环境限制。

### 3. 只观察验收

- 重启后确认 Guardian 和 Collector 自动运行，Beszel 页面可打开。
- 确认 CPU、内存、磁盘监控数据存在，容器采集为只读，Guardian/Beszel/SSH/Docker 等保护对象正确显示。
- 用状态命令确认：运行正常、模式为 observe、自动动作关闭、允许处理名单为空、两个动作入口关闭。
- 在不影响业务的前提下，触发一条已批准的低风险告警，确认页面和历史记录出现告警与恢复状态。
- 通过已批准的真实渠道向已授权收件人发送一条测试通知，并确认收件人实际收到；再确认恢复通知或恢复状态送达。没有真实送达就不能把“通知管理员”标为通过。
- 记录 SSH、Guardian、Beszel、业务健康和回滚检查结果，业务恢复必须由业务负责人确认。

### 4. 停用与回滚

- 停用：在维护窗口内停止 Guardian 相关服务，禁用开机启动，确认自动动作入口、socket 和标记不存在。
- 回滚：停止新增服务，恢复安装前保存的 Guardian 配置、systemd 文件和 drop-in，执行 `systemctl daemon-reload`，恢复原有 Beszel/Docker/SSH 状态。
- 回滚后由回滚负责人和业务负责人分别确认：服务器状态正常、业务健康正常、告警渠道未被误修改。
- 任何回滚失败都立即转带外或现场恢复，不继续尝试自动动作。

## 五、验收指标

本次验证只有在以下条件全部满足时才算通过：

1. x86_64、Ubuntu、systemd、cgroup v2、Docker、Beszel 和维护入口均由负责人确认。
2. Guardian 重启后自动运行，Collector 在线，状态命令清晰可读。
3. CPU、内存、磁盘监控入口和只读容器数据均可见。
4. Guardian、Beszel、SSH、Docker 和维护对象显示为保护对象。
5. 自动动作关闭，允许处理名单为空，两个动作入口关闭，没有容器停止、重启或删除记录。
6. 告警页面和历史记录可见，并且一条测试通知确实到达已授权收件人；恢复结果也被确认。
7. 业务负责人确认业务健康没有受到影响，回滚负责人确认能够恢复原状。
8. 日志、报告和截图中没有密码、Token、密钥、生产数据或未授权收件人信息。

## 六、立即停止条件

出现以下任一情况，立即停止验证并转人工/带外处理：

- Guardian、Collector、Beszel、SSH 或带外入口异常，或服务反复重启；
- 业务负责人报告业务异常、延迟明显上升或健康检查失败；
- 出现任何未批准的容器停止、重启、删除或服务器重启动作；
- 自动动作入口、Broker 标记/socket 或非空允许处理名单意外出现；
- 资源压力超出负责人批准范围，或根盘、内存、任务数接近无法维护的边界；
- 告警发给未授权人员、渠道配置不明或疑似凭据泄露；
- 采集数据、容器身份、审计记录或回滚材料不完整；
- 负责人、回滚负责人或业务健康负责人无法响应。

## 七、通过后的下一步

只观察验证通过后，也只能另行申请受控 `simulate`：它只展示“如果允许处理会选择谁”，不停止容器。受控 simulate 需要新的明确批准、目标范围和维护窗口。

本申请不包含生产部署，不包含生产自动动作，也不授权从非生产直接进入生产。生产需要单独的负责人评审、业务健康方案、回滚方案和自动动作审批。
