## 这次验收确认

- CPU、内存、磁盘监控入口存在，Collector 只读采集正常。
- Guardian、Beszel、SSH、Docker 和维护对象处于保护范围；保护对象能够在状态命令中看到。
- 允许处理名单为空，自动动作关闭，Broker 关闭。
- 内存链路只观察或模拟；磁盘链路只允许一次性释放 Guardian 自己的固定预留文件，并校验释放后同一文件系统的可用空间增加。
- 混合风险中资源指向不明确、磁盘没有写入源证据或数据不完整时，不停止任何容器；若配置允许，只能先释放 Guardian 自有预留并转人工处理。
- 最新工作区代码已重新安装到本地虚拟机；最终状态显示 Guardian、Collector、Beszel 正常，固定预留空间恢复为 ready。
- 本次磁盘恢复已由连续 Runtime → 固定作用域预留边界 → root 固定 helper 完成，并在共享审计库留下开始和完成记录；重复提交同一事故被拒绝，没有重放。

## 不能由本次验收推出的结论

此前维护账号 wrapper 的预留释放只能作为人工维护演示，不能证明常驻 Runtime 有权完成恢复；本次已由固定作用域预留边界替代。没有真实业务健康检查，因此预留空间释放或测试对象处理只能说明“宿主机风险已缓解，业务恢复待人工确认”，不能报告业务已经恢复。真实内存或磁盘写入业务容器的停止仍需要明确名单、完整稳定容器 ID、目标名称、`graceful_stop` 动作和一次性未过期授权；当前没有这类授权。x86_64 非生产环境和生产环境仍未验证。
