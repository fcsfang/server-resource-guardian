# 分阶段实施计划

## 阶段 0：需求与环境确认

输出：

- 目标服务器清单、OS/内核/systemd/cgroup/Docker 版本。
- 现有监控、告警、日志、审批和带外管理能力清单。
- 核心业务保护名单、可处置对象白名单和责任人。
- 生产 SLO、允许的 agent 开销和数据保留要求。
- PoC 测试机与故障演练授权。

完成标准：关键问题有明确负责人和答案，项目范围获得导师或业务负责人确认。

## 阶段 1：只观测 PoC

工作内容：

- 在一台非生产 Linux 主机部署成熟采集组件。
- 建立 CPU、内存、I/O、磁盘、网络、PSI、进程和容器仪表盘。
- 建立三级告警、通知、恢复通知和告警防抖。
- 自动生成只读现场快照，不执行任何变更动作。
- 用受控压测验证指标完整性和 agent 开销。

完成标准：所有验收场景能定位资源来源，且没有因采集导致明显业务影响。

## 阶段 2：Guardian 与人工处置

工作内容：

- 实现 Guardian 心跳、配置校验、快照、审计和固定动作接口。
- 配置 systemd/cgroup 资源保护并完成压力生存测试。
- 接入公司身份认证或审批系统。
- 只允许人工审批的限流、SIGTERM、SIGKILL、容器重启。
- 建立默认保护名单、动作超时、冷却和结果验证。

完成标准：授权动作可控、拒绝规则有效、每次动作可审计，Guardian 在压测中保持响应。

## 阶段 3：有限自动化

工作内容：

- 只选择无状态、可重建、责任明确的工作负载进入自动处置白名单。
- 先启用限流和优雅终止，再评估是否允许强制终止。
- 设置单机和全局动作次数上限、冷却、熔断及一键停用。
- 进行故障注入、误报和中心失联测试。

完成标准：自动动作在预期场景恢复服务，在不确定场景停止并升级人工，不越过保护边界。

## 阶段 4：灰度与生产推广

工作内容：

- 按“测试 -> 非核心生产 -> 核心生产”逐批灰度。
- 每批观察误报率、动作成功率、平均恢复时间和资源开销。
- 建立版本回滚、配置回滚、密钥轮换和应急停用流程。
- 形成值班手册、架构图、部署手册和故障复盘模板。

完成标准：业务负责人和运维负责人签字验收，指标达到约定目标后才扩大覆盖范围。

## 建议度量指标

- 资源危机提前发现时间。
- 告警准确率和重复告警数量。
- 从告警到确认、从确认到恢复的时间。
- 自动/人工动作成功率及误操作次数。
- 因资源耗尽导致的重启次数和业务中断时长。
- Guardian 自身 CPU、内存、磁盘和网络开销。

## 首个开发迭代的进入条件

以下信息确认后再选择语言并开始代码：

1. 首批目标 OS 与 cgroup 版本。
2. 公司现有监控平台及可用接口。
3. Docker/Kubernetes 使用情况。
4. 允许的网络拓扑和认证方式。
5. 首批可处置服务和绝对不可处置服务。
