# 定位与处置：第6–9页重构依据

本次只修订并导出第6–9页，沿用原生可编辑PPT流程和既有样式。报告日期：2026-09-17。尚无目标服务器部署与实测。

定位输出：完整对象身份、资源缓解依据、公司允许动作、候选先后顺序。没有安全候选就转人工。高占用或排名不等于根因，更不等于执行授权。

比较组合：本机查询加程序；平台数据加程序（Beszel/Netdata是例子，其数据差异见第5页）；PromQL查询加程序；Zabbix模板/触发器加脚本。比较共同的四个问题：找到什么对象、处理谁可能有效、谁允许处理、多个候选如何选择。不是四种互斥产品，也不宣称列尽所有定位方式。候选排序、业务配置、数据时效与身份复核属于工程设计；尚无自动选择效果或工时比较。

处置输出：动作记录、资源与业务复查结果、必要的升级处理及后续恢复安排。比较本机程序、Monit加脚本、Zabbix加脚本、已有Ansible流程分别可复用的动作、复核、失败控制和恢复检查。所有方案都需要公司的业务授权和恢复标准。脚本是补缺方式；已有流程与本机程序可组合，但执行主责和重复控制必须清楚。

## 官方资料与证据边界

- [Docker标签](https://docs.docker.com/engine/manage-resources/labels/)：标签承载业务元数据；容器标签在对象生命周期内为静态。标签本身不证明授权可信，需公司维护配置。
- [Prometheus查询运算符](https://prometheus.io/docs/prometheus/latest/querying/operators/)：标签匹配、条件筛选、topk排序。查询表达式不能替代业务许可或根因诊断。
- [Zabbix Docker模板](https://www.zabbix.com/integrations/docker)：容器发现与监控项；精确字段及Docker29适配仍需实测。
- [Zabbix计算项](https://www.zabbix.com/documentation/7.4/en/manual/config/items/itemtypes/calculated)：计算已有数据，需配置更新周期和公式；此前长页提取截断，使用官方检索结果确认概念，不提供未经验证的参数代码。
- [Zabbix远程命令](https://www.zabbix.com/documentation/7.4/en/manual/config/notifications/action/operation/remote_command)：预配置命令、执行位置和相关超时。执行前的动态容器身份与权限复核由本方案本机脚本补充。
- [Zabbix操作升级](https://www.zabbix.com/documentation/7.4/en/manual/config/notifications/action/escalations)：安排操作步骤；并不保证对同一业务目标跨事件互斥。
- [Zabbix恢复操作](https://www.zabbix.com/documentation/current/en/manual/config/notifications/action/recovery_operations)：问题恢复时支持消息与命令；问题恢复状态不自动等于业务已经恢复。以上Zabbix动作能力通过Anysearch官方域检索结果核对，本次未给出具体版本参数或可直接部署配置。
- [Monit手册](https://mmonit.com/monit/documentation/monit.html)：固定对象检查、启停程序、程序超时、服务重启限次和协议检查。Anysearch提取在长文位置截断，另读取同一官方页面的SERVICE RESTART LIMIT正文，确认可在规定检查周期内达到重启次数时unmonitor。当前页面是6.0.0，不证明Ubuntu软件源版本支持完全相同细节。服务重启限次不能泛化为所有自定义EXEC动作自动限次。
- [Docker stop](https://docs.docker.com/reference/cli/docker/container/stop/)：停止信号、宽限期及可能的强制终止，需要业务允许。
- [Docker update](https://docs.docker.com/reference/cli/docker/container/update/)：可调整部分运行时资源配置；动态降低内存限额并非无风险释放内存方法。
- [Ansible失败处理](https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_error_handling.html)：failed_when、失败处理等机制，具体标准要编写。
- [Ansible等待重试](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_loops.html)：until、retries、delay；本页未固定默认参数。
- [Ansible block](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_blocks.html)：失败分支不覆盖所有不可达等错误。Ansible流程不是自动常驻本机的紧急保护守卫，跨运行互斥与调用入口需设计。
- [Ubuntu Jammy资源控制](https://manpages.ubuntu.com/manpages/jammy/man5/systemd.resource-control.5.html)：ManagedOOMPreference可影响内存专项候选，但有权限、扩展属性和不递归等限制。本次仅保留其内存专项边界，细节留原附录，不把它当作全资源定位平台。
