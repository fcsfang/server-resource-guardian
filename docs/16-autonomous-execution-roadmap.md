# 自动化执行路线与 Agent 接手协议

> 本文件是项目后续执行的总路线。它回答“下一步做什么、何时算完成、哪些事情必须停下来请求确认”，用于当前 Agent 或后续 Agent 无监督接手。

## 1. 总目标

构建一个默认安全的 Guardian：在宿主机或容器出现可复现的宕机风险时，完成“实时检测 → 风险对象定位 → 保护策略判断 → 分级处置 → 恢复验证或升级人工”的闭环。

本项目不以给所有 Docker 容器统一设置内存上限为目标。Docker/systemd/cgroup 资源边界只在业务明确允许时作为某个对象的可选防线。

按顺序推进，完成一项再进入下一项：

1. 获得明确的本地可丢弃对象授权后，完成一次 `graceful_stop` 的真实闭环实验，并记录动作前后快照。

## 4. 设计和实现约束

- 默认模式永远是 `observe`；测试动作先使用 `simulate`。
- 未知对象、保护名单对象和无法确认归属的对象默认拒绝自动处置。
- 自动动作按风险等级从低到高排列：记录/告警 → 优雅停止或降载 → 受控重启 → 人工升级；强制终止必须显式授权。
- 每次风险事件都要记录采样时间、信号、对象、决策、动作、快照、结果、冷却状态和恢复验证。
- 任何阈值先标为本地校准值，不能直接写成生产阈值。
- 资源限制不是默认修复动作；不能因为实验方便而改变所有业务容器的资源配置。
- 生产连接、故障注入、真实终止/重启、凭据配置、删除虚拟机或批量删除文件必须暂停请求确认。

## 5. 无监督执行循环

每次开始工作时按以下顺序执行：

1. 读取 `README.md`、`PROGRESS.md`、`goals/README.md`、当前 Goal、本文件和相关实验记录。
2. 检查 Git 状态、当前分支、Mac Ubuntu 实例状态和最近实验结果。
3. 选择“下一项执行队列”中第一个未完成且不依赖外部授权的任务。
4. 先写验收条件，再做最小改动；实验前先建立 `EXP-###` 记录和停止条件。
5. 只在本地、可丢弃测试对象上执行有界实验；压力逐级增加，出现救援链路退化就停止扩大压力。
6. 验证结果，更新 Goal、实验记录和 `PROGRESS.md`，明确区分已验证、推断和待确认。
7. 提交可审查的变更；网络可用时同步到 GitHub，网络不可用时保留本地提交并记录原因。
8. 遇到生产、凭据、不可逆操作、外部授权或关键需求歧义时停止该分支，只报告阻塞点并继续其他安全任务。

## 6. 完成定义

Goal 4 只有同时满足以下条件才算完成：

- 能在明确检测窗口内发现可复现的宕机风险信号；
- 能定位到具体容器、cgroup、进程组或主机级对象；
- 保护名单和未知对象默认拒绝策略经过测试；
- `observe`、`simulate`、`enforce` 边界清晰，默认不会产生破坏性动作；
- 每次动作都有审计、快照、恢复验证和失败升级结果；
- 在可丢弃测试对象上完成至少一轮真实闭环；
- 结论明确标注 ARM64 本地验证与 x86_64/生产待复核边界。
