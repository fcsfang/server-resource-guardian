## 1. 交付目标

交付包必须让组长在一次演示中回答四个问题：

1. 没有 Guardian 时，系统具体会出现什么错误？

3. Beszel 在方案中承担什么职责，是否越权？
4. 下一步需要申请什么环境和授权？

## 3. 效果评测口径

主指标按以下优先级排列：

1. 是否阻断宿主机级 global OOM 或同类级联错误；
2. 是否在失效前发现风险并定位对象；
3. 是否只对获准对象执行获准动作；
4. 动作后资源和健康检查是否恢复；
5. 高压时人工 SSH/诊断/停止链路是否保留；
6. Guardian、Beszel 的额外资源和数据延迟是否可接受。

CPU/内存是否比原来低、是否给所有容器设置统一内存上限，不是本项目的首要成功标准。

## 4. 证据边界

- EXP-021 是 Guardian 有效性的主对照；EXP-028 是 Beszel 与 Guardian 时效性的主对照。
- 当前数据只证明本地 ARM64、可丢弃对象和本地健康探针场景。
- 真实业务 health check、生产保护名单、x86_64 兼容性和生产授权仍需外部条件。
- G6-T06 的正式外部评审未完成前，只提供静态演示，不实现 Beszel 上游修改或生产 endpoint。

## 5. 明早验收顺序

1. 打开离线演示页，先看“效果对照”。
2. 点击“Beszel 集成”，说明监控和处置的权限边界。
3. 点击“现场回放”，播放检测→定位→计划→恢复链路。

5. 运行测试命令，展示 66/66 宿主机结果和 Multipass 结果。
6. 最后说明需要组长批准的非生产 x86_64 observe 申请，不把本地结果写成生产承诺。
