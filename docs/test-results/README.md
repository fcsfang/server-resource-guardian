# 测试结果目录

本目录保存已经脱敏、可复现、可审阅的测试结论。它与 `reports/` 的边界如下：

- `reports/`：机器本地原始报告、日志、快照和生产采集结果，默认不提交。
- `docs/test-results/`：整理后的测试记录，可以提交并作为双机同步依据。

## 命名

```text
YYYY-MM-DD-<scenario>.md
```

例如：

```text
2026-09-20-cpu-rescue-ssh.md
2026-09-20-memory-pressure-oomd-observe.md
```

## 最小记录结构

每份结果至少记录：

1. 测试目的与对应层次：救援能力保障 / 自动资源保护。
2. 测试环境：OS、内核、systemd、cgroup、Docker、组件版本。
3. 授权范围、测试对象和保护名单。
4. 前置状态、注入方法、开始/结束时间。
5. 观测结果：SSH、shell、诊断命令、压力指标、快照和组件开销。
6. 动作结果：是否只读、是否模拟、是否执行了真实变更。
7. 验收结论、异常、证据路径和后续待确认项。
8. 明确的停止条件与回滚结果。

不要在这里保存密码、token、生产原始日志或未经脱敏的业务标识。完成测试后，在 `PROGRESS.md` 增加链接和一句话结论。
